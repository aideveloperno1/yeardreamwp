# RAG 검색 품질 평가 (Retrieval Evaluation)

**담당:** AI 분석가 1

「산업안전보건기준에 관한 규칙」 기반 RAG 시스템의 검색 품질을 평가하고, 검색 방식별 성능 비교를 통해 프로젝트에 적합한 검색 모델을 선정합니다.

본 디렉터리에는 검색 모델 비교 실험 코드, 평가 데이터 로딩 코드 및 검색 품질 평가 보고서를 관리합니다.

## 1. 평가 개요

본 평가는 사용자 질문에 대해 정답 근거 조문이 검색 결과 상위에 포함되는지 확인하는 것을 목적으로 합니다.

기존 검색 환경인 `nomic-embed-text`, 키워드 기반 검색 방식인 `BM25`, 다국어 임베딩 모델인 `bge-m3`를 비교하였습니다.

개발용 평가 데이터로 검색 방식을 비교하고, 선정된 모델을 별도의 최종 평가 데이터로 검증하였습니다.

### 평가 환경

| 항목 | 내용 |
|---|---|
| 평가 대상 | 산업안전보건기준에 관한 규칙 |
| 기준 문서 | 2026.03.02 시행본 PDF |
| 검색 대상 | 법령 청크 684개 |
| 임베딩 모델 | nomic-embed-text, bge-m3 |
| 비교 검색 방식 | Dense Retrieval, BM25 |
| Vector DB | ChromaDB |
| 임베딩 실행 환경 | Ollama |
| 검색 결과 수 | Top-5 |
| 평가 데이터 | 개발용 15문항, 최종 평가용 15문항 |
| 평가 지표 | Hit@1, Hit@3, Hit@5, MRR@5 |
| 정답 판정 | 검색된 조문 번호와 정답 조문 번호 일치 여부 |

## 2. 평가 방법

### 2.1 검색 방식 비교

| 검색 방식 | 설명 |
|---|---|
| nomic-embed-text | 기존 RAG 검색 환경에서 사용한 임베딩 모델 |
| BM25 | 공백 기준 토큰화를 적용한 키워드 기반 검색 |
| bge-m3 | 별도의 ChromaDB를 구축하여 평가한 다국어 임베딩 모델 |

### 2.2 평가 지표

- **Hit@1:** 검색 결과 1위에 정답 조문이 포함된 질문의 비율
- **Hit@3:** 검색 결과 상위 3개에 정답 조문이 포함된 질문의 비율
- **Hit@5:** 검색 결과 상위 5개에 정답 조문이 포함된 질문의 비율
- **MRR@5:** 상위 5개 검색 결과에서 정답 조문이 처음 등장한 순위의 역수를 질문별로 계산한 평균

정답 여부는 검색 문서의 `article_number` 메타데이터와 평가 데이터의 `gold_articles`를 비교하여 판단합니다.

본 평가는 Retrieval 단계에 한정하며, LLM이 생성한 최종 답변의 정확성을 직접 평가하지 않습니다.

### 2.3 평가 데이터 분리

전체 30문항을 다음과 같이 분리하였습니다.

| 구분 | 문항 수 | 목적 |
|---|---:|---|
| 개발용 (Development) | 15 | 검색 방식 비교 및 모델 선정 |
| 최종 평가용 (Test) | 15 | 선정된 검색 모델의 성능 확인 |

개발용 평가에서 검색 방식을 선정한 뒤, 별도로 분리한 최종 평가용 문항에 적용하였습니다.

단, 전체 질문은 법령 기반으로 작성되었으므로 실제 사용자 질문의 다양성을 충분히 대표하지는 않습니다.

## 3. 디렉터리 및 파일 구성

### 검색 평가 코드

| 파일 | 설명 |
|---|---|
| `load_eval_data.py` | 개발용·최종 평가용 질문과 정답 조문 데이터 로딩 |
| `evaluate_retrieval.py` | 기존 검색 환경의 nomic-embed-text 평가 |
| `compare_bm25.py` | BM25 검색 성능 평가 |
| `build_bge_db.py` | bge-m3 전용 ChromaDB 구축 |
| `evaluate_bge.py` | bge-m3 개발용 15문항 평가 |
| `evaluate_bge_test.py` | bge-m3 최종 평가용 15문항 평가 |
| `RETRIEVAL_REPORT.md` | 검색 방식 비교 결과 및 평가 한계 분석 |

### 평가 데이터

평가 데이터는 프로젝트 최상위의 `evaluation/` 폴더에서 관리합니다.

| 파일 | 설명 |
|---|---|
| `questions_dev_15.json` | 개발용 평가 질문 15개 |
| `questions_test_15.json` | 최종 평가용 질문 15개 |
| `evidence.json` | 개발용 평가 질문별 정답 근거 조문 |
| `evidence_test_15.json` | 최종 평가용 질문별 정답 근거 조문 |

각 평가 질문은 `case_id`를 기준으로 해당 정답 근거 조문과 연결됩니다.

## 4. 실행 환경 및 준비

모든 명령어는 별도 안내가 없는 한 **프로젝트 최상위 디렉터리**에서 실행합니다.

### 4.1 Python 패키지 설치

Python 가상환경을 활성화한 후 필요한 패키지를 설치합니다.

```powershell
pip install -r requirements.txt
pip install rank-bm25
```

`rank-bm25`는 BM25 비교 실험에 필요한 추가 패키지입니다.

### 4.2 Ollama 임베딩 모델 준비

로컬 Ollama가 설치 및 실행되어 있어야 합니다.

```powershell
ollama pull nomic-embed-text
ollama pull bge-m3
```

### 4.3 법령 PDF 준비

다음 PDF를 프로젝트 루트의 `upload/` 폴더에 준비합니다.

```text
산업안전보건기준에 관한 규칙(고용노동부령)(제00450호)(20260302).pdf
```

본 평가에서는 해당 법령 PDF를 조문 단위로 분할하고, 긴 조문은 추가로 분할한 청크를 사용합니다.

### 4.4 Vector DB 준비

| 경로 | 용도 |
|---|---|
| `store/` | 기존 서비스 검색 환경 |
| `store_bge/` | bge-m3 비교 실험용 DB |

기존 검색 환경을 평가하려면 해당 환경에서 생성한 DB가 준비되어 있어야 합니다.

bge-m3 실험용 DB는 다음 명령어로 구축합니다.

```powershell
python -m analysis.retrieval.build_bge_db
```

**주의:** `build_bge_db.py`는 `store_bge/` 경로가 이미 존재하면 실행을 중단합니다. 기존 실험 DB가 있다면 내용을 확인한 후 재구축 여부를 결정해야 합니다.

또한 임베딩 모델이 다른 DB를 혼용하지 않도록 주의해야 합니다.

## 5. 검색 성능 평가 실행

### 5.1 개발용 평가

**기존 검색 환경 평가**

```powershell
python -m analysis.retrieval.evaluate_retrieval
```

**BM25 평가**

```powershell
python -m analysis.retrieval.compare_bm25
```

**bge-m3 평가**

```powershell
python -m analysis.retrieval.evaluate_bge
```

각 코드는 개발용 15문항을 대상으로 검색 결과의 정답 조문 순위를 확인하고 Hit@1, Hit@3, Hit@5 및 MRR@5 평균을 출력합니다.

### 5.2 최종 평가

개발용 평가에서 선정한 bge-m3를 최종 평가용 15문항에 적용합니다.

```powershell
python -m analysis.retrieval.evaluate_bge_test
```

해당 코드는 `load_eval_data(split="test")`를 사용하여 최종 평가 데이터를 불러옵니다.

최종 평가에서는 개발용 평가와 동일한 Top-5 검색 및 조문 번호 일치 기준을 적용합니다.

## 6. 검색 품질 평가 결과

### 6.1 개발용 15문항 비교

| 검색 방식 | Hit@1 | Hit@3 | Hit@5 | MRR@5 |
|---|---:|---:|---:|---:|
| nomic-embed-text | 0.0000 | 0.0000 | 0.0000 | 0.0000 |
| BM25 | 0.6667 | 0.8667 | 0.8667 | 0.7556 |
| **bge-m3** | **1.0000** | **1.0000** | **1.0000** | **1.0000** |

개발용 15문항에서 bge-m3는 모든 질문의 정답 조문을 검색 결과 1위에 배치하였습니다.

BM25는 15문항 중 13문항에서 정답 조문을 Top-5 이내에 검색하였으며, LAW-016과 LAW-020에서 검색에 실패하였습니다.

기존 nomic 기반 검색 환경에서는 모든 질문의 정답 조문이 Top-5에 포함되지 않았습니다.

다만 기존 DB 구축에 사용된 임베딩 모델과 평가 당시 검색 모델의 완전한 일치 여부를 검증하지 못했으므로, 해당 결과만으로 nomic-embed-text 자체의 검색 성능이 낮다고 단정할 수 없습니다.

### 6.2 검색 모델 선정

개발용 평가 결과를 기준으로 **bge-m3를 최종 평가 대상 검색 모델로 선정**하였습니다.

선정 근거는 다음과 같습니다.

- 개발용 15문항에서 Hit@1 및 Hit@5 모두 1.0000 기록
- 모든 평가 질문에서 정답 조문을 검색 결과 1위에 배치
- 현재 평가 환경에서 다른 비교 검색 방식보다 높은 성능 기록

### 6.3 최종 평가용 15문항 결과

| 평가 지표 | 개발용 15문항 | 최종 평가용 15문항 |
|---|---:|---:|
| Hit@1 | 1.0000 | 1.0000 |
| Hit@3 | 1.0000 | 1.0000 |
| Hit@5 | 1.0000 | 1.0000 |
| MRR@5 | 1.0000 | 1.0000 |

bge-m3는 최종 평가용 15문항에서도 모든 정답 조문을 검색 결과 1위에 배치하였습니다.

따라서 현재 법령 데이터와 평가 조건을 기준으로 bge-m3가 높은 검색 성능을 보였음을 확인하였습니다.

단, 이 결과는 전체 30개 법령 기반 평가 문항에 한정되며 실제 서비스의 모든 질문에서 동일한 성능을 보장하지는 않습니다.

## 7. 평가의 한계

본 평가에는 다음과 같은 한계가 있습니다.

1. **평가 데이터 규모:** 전체 30문항으로 실제 사용자 질문의 다양성을 대표하기 어렵습니다.
2. **질문 구성:** 법령 내용을 기반으로 질문을 작성했으므로 실제 사용자 특유의 구어체, 오타 및 모호한 표현에 대한 검증이 부족합니다.
3. **정답 판정 기준:** 조문 번호 일치 여부만 평가하므로 정확한 항·호 또는 충분한 답변 근거가 검색되었는지는 보장하지 않습니다.
4. **평가 문항 독립성:** 서로 다른 질문이 동일한 정답 조문을 갖는 경우가 있어 평가 데이터의 독립성에 한계가 있습니다.
5. **기존 모델 비교 환경:** nomic 기반 DB의 임베딩 설정 일치 여부를 완전히 검증하지 못했으므로 모델 간 순수 성능 비교로 해석하기 어렵습니다.
6. **BM25 토큰화:** 공백 기준 토큰화를 사용하였으며, 한국어 형태소 분석을 적용한 BM25와는 비교하지 않았습니다.
7. **답변 생성 평가 제외:** 검색 품질 평가만 수행했으며 최종 LLM 답변의 정확성, 환각 및 근거 충실성은 평가 범위에 포함하지 않았습니다.

## 8. 결론

현재 평가 환경에서는 **bge-m3가 가장 높은 검색 성능을 기록**하였습니다.

개발용 15문항과 별도로 분리한 최종 평가용 15문항에서 모두 Hit@1 및 MRR@5 1.0000을 기록하여 프로젝트의 RAG 검색 모델로 채택할 것을 권장합니다.

다만 실제 서비스 적용 전에는 실제 사용자 표현을 반영한 질문으로 추가 평가하고, 검색된 조문이 최종 LLM 답변의 근거로 올바르게 활용되는지 검증할 필요가 있습니다.
